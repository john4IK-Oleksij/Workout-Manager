# SPEC 01 — Фундамент проєкту та підключення до MySQL

## 1. Мета завдання

Створити початкову структуру проєкту, налаштувати Python-середовище, встановити необхідні залежності, ініціалізувати FastAPI та забезпечити підключення до MySQL / MariaDB 10.4.32 через SQLAlchemy 2.1 і PyMySQL.

Це фундамент для всіх наступних етапів реалізації.

Дотримуватися вимог:
- `mission.md` — загальна місія проєкту.
- `ORM_MySQL(1).docx` — основне технічне завдання.
- Навчальна презентація «Агрегатні функції в SQLAlchemy» — технічна та методична основа.

На цьому етапі НЕ створювати ORM-моделі, таблиці бази даних, CRUD-ендпоінти та агрегатні запити.

## 2. Технології

Використовувати:

- Python
- FastAPI
- Uvicorn
- SQLAlchemy 2.1
- PyMySQL
- Pydantic 2
- python-dotenv

Використовувати сучасний синтаксис SQLAlchemy 2.x.

Не використовувати застарілий синтаксис SQLAlchemy.

## 4. Залежності

Створити файл `requirements.txt`.

Додати необхідні залежності:

- fastapi
- uvicorn

- pymysql
- pydantic
- python-dotenv

Використовувати сумісні стабільні версії.

Версія SQLAlchemy повинна відповідати вимозі SQLAlchemy 2.1.

Не встановлювати зайві бібліотеки без технічної необхідності.

## 5. Конфігурація середовища

Створити файл `.env.example` із такими змінними:

```env
APP_NAME=Workout Tracking API
APP_ENV=development

DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_password
DB_NAME=workout_tracker
```

Реальні налаштування зберігати в локальному файлі `.env`.

Вимоги:

1. Використовувати `python-dotenv` для завантаження локального `.env`.
2. Не записувати реальні облікові дані бази даних безпосередньо в Python-коді.
3. Додавати `.env` до `.gitignore`.
4. Не передавати паролі та інші секрети в Git.
5. Використовувати змінні середовища для конфігурації підключення.

## 6. Підключення до бази даних

Реалізувати `app/database.py`.

### Обов'язкові вимоги

1. Створити URL підключення до MySQL через діалект `mysql+pymysql`.
2. Отримувати параметри підключення зі змінних середовища.
3. Створити SQLAlchemy engine через `create_engine()`.
4. Обов'язково встановити `hide_parameters=True`.
5. Встановити `pool_pre_ping=True`.
6. Створити `SessionLocal` через `sessionmaker`.
7. Встановити `autocommit=False`.
8. Встановити `autoflush=False`.
9. Використовувати конфігурацію сесій SQLAlchemy 2.x.
10. Реалізувати залежність FastAPI `get_db()`.

### Вимоги до `get_db()`

Функція повинна:

- Створювати сесію бази даних.
- Передавати її через `yield`.
- Гарантовано закривати сесію після завершення запиту.
- Закривати сесію навіть у випадку виникнення помилки.

Використовувати конструкцію `try/finally`.

На цьому етапі не створювати таблиці бази даних.

Не виконувати SQL-запити для роботи з предметними даними.

## 7. Ініціалізація FastAPI

Реалізувати `app/main.py`.

### Вимоги

1. Створити екземпляр FastAPI.
2. Використати назву застосунку з конфігурації.
3. Реалізувати тестовий endpoint:

`GET /health`

Очікувана відповідь:

```json
{
  "status": "ok",
  "application": "Workout Tracking API"
}
```

Endpoint повинен повертати HTTP 200.

Перевірка `/health` не повинна вимагати підключення до бази даних.

Не створювати поки що роутери користувачів, тренувань і статистики.

Залишити `main.py` простим і зрозумілим.

## 10. Порядок перевірки

Виконати послідовно:

1. Створити та активувати віртуальне середовище Python.
2. Встановити залежності з `requirements.txt`.
3. Створити локальний `.env` на основі `.env.example`.
4. Запустити MySQL / MariaDB 10.4.32.
5. Переконатися, що налаштована база даних існує.
6. Запустити застосунок:

```bash
uvicorn app.main:app --reload
```

7. Відкрити:

`http://127.0.0.1:8000/health`

8. Відкрити:

`http://127.0.0.1:8000/docs`

9. Окремо перевірити, що SQLAlchemy може встановити реальне з'єднання з MySQL.

Якщо підключення не працює, визначити справжню причину помилки, не розкриваючи пароль або інші конфіденційні параметри.

Важливо: успішний запуск FastAPI сам по собі НЕ означає, що підключення до MySQL перевірено.
